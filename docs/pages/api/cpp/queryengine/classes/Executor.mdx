### getChunkRequestInfo [#getchunkrequestinfo]

<CodeBlock links={{"Executor": "executor", "InputDescriptor": "inputdescriptor", "InputTableInfo": "../structs/inputtableinfo", "ChunkRequestInfo": "../executorresourcemgrnamespace/structs/chunkrequestinfo"}}>
```cpp showLineNumbers={false}
ExecutorResourceMgr_Namespace::ChunkRequestInfo Executor::getChunkRequestInfo(
    const ExecutorDeviceType device_type,
    const std::vector<InputDescriptor> &input_descs,
    const std::vector<InputTableInfo> &query_infos,
    const std::vector<std::pair<int32_t, FragmentsList>> &device_fragment_lists
) const
```
</CodeBlock>

Determines a unique list of chunks and their associated byte sizes for a given query plan.

Called by Executor::launchKernelsViaResourceMgr

Note that we currently need the kernel's fragment lists generated in Executor::createKernels (which calls [QueryFragmentDescriptor::buildFragmentKernelMap](queryfragmentdescriptor#buildfragmentkernelmap)), but would be nice to hoist that logic out so that we could call this earlier, i.e. before compilation such that we don't waste compilation cycles in an attempt to run a query on GPU, only to see there are insufficient resources for it and it must be kicked to CPU

Note this method currently has two key limitations:

1. Only accounts for chunks in the lhs table if a join is involved.
2. Conservatively estimates that column widths for intermediate results are always 8 bytes, when in some cases they may have a lower byte width.

**Returns:** [ExecutorResourceMgr_Namespace::ChunkRequestInfo](../executorresourcemgrnamespace/structs/chunkrequestinfo) - contains various info used by ExecutorResourceMgr to gate (and soon optimize scheduling of) query step resource requests.

**Parameters**

<ParamField path="device_type" type="const ExecutorDeviceType">
- Specifies whether the query needs CPU or GPU buffer pool memory
</ParamField>

<ParamField path="input_descs" type="const std::vector<InputDescriptor> &">
- Tables needed by the query
</ParamField>

### launchKernelsViaResourceMgr [#launchkernelsviaresourcemgr]

<CodeBlock links={{"Executor": "executor", "SharedKernelContext": "sharedkernelcontext", "ExecutionKernel": "executionkernel", "InputDescriptor": "inputdescriptor", "QueryMemoryDescriptor": "querymemorydescriptor"}}>
```cpp showLineNumbers={false}
void Executor::launchKernelsViaResourceMgr(
    SharedKernelContext &shared_context,
    std::vector<std::unique_ptr<ExecutionKernel>> &&kernels,
    const ExecutorDeviceType device_type,
    const std::vector<InputDescriptor> &input_descs,
    const QueryMemoryDescriptor &query_mem_desc,
    const size_t available_cpus
)
```
</CodeBlock>

Launches a vector of kernels for a given query step, gated/scheduled by ExecutorResourceMgr.

This function first calculates the neccessary CPU, GPU, result set memory and buffer pool memory neccessary for the query, which it then requests from ExecutorResourceMgr. The query thread will be conditionally put into a wait state until there are enough resources to execute the query, which might or might not be concurrently with other query steps, depending on the resource grant policies in place and the resources needed by this thread's query step and all other in-flight queries requesting resources. After the thread is given the green light by ExecutorResourceMgr, it then calls launchKernelsImpl which does the actual work of launching the kernels.

**Parameters**

<ParamField path="shared_context" type="SharedKernelContext &">
- Used to obtain [InputTableInfo](../structs/inputtableinfo) vector (query_infos) used for input chunk calculation
</ParamField>

<ParamField path="kernels" type="std::vector<std::unique_ptr<ExecutionKernel>> &&">
- Vector of kernels that will be launched, one per fragment for CPU execution, but can be multi-fragment (one per device) for GPU execution
</ParamField>

<ParamField path="device_type" type="const ExecutorDeviceType">
- Specifies whether the query step should run on CPU or GPU
</ParamField>

<ParamField path="input_descs" type="const std::vector<InputDescriptor> &">
- Neccessary to get the input table and column ids for a query for input chunk calculation
</ParamField>

<ParamField path="query_mem_desc" type="const QueryMemoryDescriptor &">
- Neccessary to get result set size per kernel
</ParamField>

### serializeLiterals [#serializeliterals]

<CodeBlock links={{"Executor": "executor"}}>
```cpp showLineNumbers={false}
std::vector<int8_t> Executor::serializeLiterals(
    const std::unordered_map<int, CgenState::LiteralValues> &literals,
    const int device_id
)
```
</CodeBlock>

Serialize variants from CgenState::LiteralValues into a std::vector&lt;int8_t&gt;.

The returned std::vector&lt;int8_t&gt; has two consecutive sections:

- Header: One entry for each literal (lit) whose size is given by LiteralBytes&#123;&#125;.
If lit is a fundamental type, then store the value directly.
If lit is a std::pair&lt;std::string, shared::StringDictKey&gt; store the string id.
If lit is any other variable length type, store a packed offset and length. All values are aligned according to their size. For example if only a double is followed by an int32_t then they are simply stored consecutively. If they are reversed then the double must be aligned to an 8-byte offset, leaving a gap of 4 bytes in between them.
